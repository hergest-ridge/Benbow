# UX

## Principles
1. **Instant.** Everything opens from the local cache. Writes are optimistic. No spinners for local data.
2. **Smooth.** 120 Hz, zero jank in feeds, shared-element transitions, predictive back, spring motion, subtle haptics. Telegram is the bar.
3. **Seamless text.** It reads and edits like a notebook, not a block database (see editor.md).
4. **Low friction.** Capture in under 3 seconds. Metadata is optional and can always be added later.
5. **Forgiving.** Undo everywhere, trash instead of delete, version history, input that never gets lost.
6. **Calm.** Warm, paper-like, unhurried. No guilt mechanics, no noisy badges.
7. **Every input.** What a finger swipes, a mouse drags: every horizontal row, strip and pager takes `Modifier.mouseSwipe(state)` (or `sideScroll` for a plain scrolling row), new ones too (ADR-048).

## Navigation (phone)
Bottom bar: **Главная · Лента · Календарь · Поиск · Ещё**. The quick-capture composer lives on Home only. "Ещё" (Mihon-style "More") holds the rest: server and sync, reminders, tags, trash, later settings; planned (7.18, ADR-041): «Медиатека» as an item of its own near the top. Trackers (7.21, ADR-050): «Ещё → Трекеры» on a phone, with Home blocks leading there; on the web and the desktop a tab «Трекеры» after «Записки».
Motion (owner's feedback, 2026-10-13): tabs switch in place, no animation. A screen opened on top fades in over the one below (220 ms); Back and the predictive back gesture fade it away (no scale-down). The tab bar is the compact M3 Expressive `ShortNavigationBar`; it stays in place while the keyboard is up (the keyboard covers it and slides off it), and screens above get the keyboard inset minus the bar.
Desktop and web: navigation rail + adaptive list-detail panes (Material 3 adaptive), with keyboard shortcuts.
As built (6.6): from 840 dp wide (desktop, tablets) a navigation rail replaces the bottom bar and screens are centred at up to 820 dp; the layout tree keeps its shape, so resizing never rebuilds screens. Desktop: closing the window hides it to the tray (reminders and sync keep running; a one-time notification says so), tray menu Открыть / Новая запись / Выход, window size and place remembered (a place on a missing monitor falls back), files dragged from Explorer onto an entry are attached, shortcuts Ctrl+N, Ctrl+F, Ctrl+1…6 (the tabs; six with «Трекеры» since 0.17.1), Ctrl+S (save a version), Alt+← (listed under "Ещё → Сочетания клавиш"). The native Windows title bar is painted in the app's background and text colors through DWM (JNA 5.19.1; caption color on Windows 11, dark caption on Windows 10), so it blends in while snap layouts, shadow, rounded corners and edge resizing stay native. As built (W4, 2026-10-16, desktop and web): from 1040 dp wide the tab's screen stays on the left (400 dp) and what it opens shows on the right (centred at up to 820 dp): a post, an entry, comments, a page from "Ещё"; the entry open on the right is framed in the list. Picking another item replaces the right side instead of stacking; Back (or the post's back arrow) closes it, and an empty right side shows the wordmark, a hint and "Новая запись". The rail stays beside an open entry; the media viewer and the drawing canvas take the whole window, laid out over the rail, which stays put beneath them so nothing jumps aside (ADR-060). Web: the address follows the screen (`#/feed`, `#/entry/<id>`, `#/server`; a reload, a bookmark or a typed address opens it), and the browser's Back, Alt+← and a mouse's side button go back in the app; at its first screen they leave the page. Web keys: Alt+N new entry and Alt+1…6 tabs (the browser keeps Ctrl+N and Ctrl+1…6), Ctrl+F search, Ctrl+S save a version; "Ещё → Сочетания клавиш" lists them. A loading screen (the lantern icon and a thin bar) covers the first seconds and fades out; the tab icon is the app icon; a failed start says so there. As built (W5): "Ещё → Экспорт" downloads the ZIP; "Импорт из файла…" in the calendars panel takes Google's ZIP or an `.ics`; reminders ring while the tab is open, as a system notification once the browser may show them (asked when a reminder is added), otherwise as a message in the app. As built (owner's web feedback, 2026-10-16, server 0.7.2): the line between the list and the right side drags (the list 300 to 640 dp, the right side keeps at least 480; remembered per device, a double click puts it back to 400); with a mouse (desktop and web) every carousel and the viewer get round translucent ‹ › buttons at the sides, hidden at either end (touch screens keep swiping only); in the viewer ← and → page and Esc closes; whatever can be clicked shows the pointing hand; a carousel is at most 70% of the window tall (phones never reach it), and pictures in the text stay at most 520 dp tall as before.

It takes its colors from the cover (the cover's main color as the seed of the app's scheme, a gradient from its container color down to the surface): «Сейчас играет» and ⌄ on top, the cover across the width (it sinks back a little while paused), title, artist · album, the seek bar with the time played and the time left, previous / play / next (previous restarts a track after 3 s), «К записи», then «Далее»: the tracks to come, a tap skips to one. A recording key pauses the music; so does a video in the viewer. A sound opened in the viewer plays through the player. Android plays on in the background with the system's media notification, the lock screen and headset buttons; the browser's media keys and panel work too.
- **Search:** instant FTS with filters (date range, tags, kind, has-media, favorites, mood), saved searches.
- **Settings / Server:** connection (host:port, pairing QR scan), sync status, backup status (last verified backup), cache policy, theme, app lock.
- **The look of a note** (ADR-047, ADR-052, ADR-054): «Оформление записки» lists its parts (color, font, paper, pattern, light, motion, scrapbook) with what is chosen in each; a part opens as a grid that scrolls down, never sideways. On a phone a sheet with the note's preview on top; in a wide window a pane beside the open note, the page against the feed, a line between them that moves, ✕ to close, nothing over anything. Fonts: the app's eight, the server's pack and the owner's own, handwritten first; «Шрифты записок в ленте» in «Оформление» shows them in the feed too.
- **Trackers** (7.21, ADR-050; out of labs in 0.17.1): a list of one's trackers (a tracker's menu, on a long press or its «⋮»: up and down, «Настроить трекер», the archive, the trash; dragging later) and «Новый трекер» from a preset or a blank sheet. A tracker opens as its sheet: the month as on paper (days down the page with weekday letters, today's row marked (the clock's date from midnight, not the journal's 04:00, ADR-053), months by swipe like the calendar), its columns across with their icon and header text (the short one where narrow), a footer of totals that only count up; an eye in the title bar hides or shows its numbers in one tap (totals, averages, goals' numbers; counts then show as fills), remembered per tracker on every device. Cells answer by type: a check toggles with a tap; a count adds one per tap, a long press opens the exact number and a note; a rating or a choice opens a small row of its values in their colors; a note opens a line to type. A time column has a day's spans in a sheet (the timers are gone, ADR-058); the sleep sheet shows days × hours (`hours`; the preset's a whole day from midnight, ADR-051): a tap paints or clears an hour, a drag along a row paints the hours it passes (clears them when it starts on a painted one; a mouse drags at once, a finger after a long press), a long press alone opens the day's spans to type their times; the painted hours are snakes that spring and stretch after the pointer (ADR-058), and a drag from a snake's end outwards stretches it (ADR-059); a mouse lights the cell or hour under it, and its right click clears a day with «Вернуть»; a month can lie across instead («Настроить трекер → Месяц на листе»: days along the top, columns down the side, a sleep column's hours as rows painted down a day); «Оформление трекера» also sets «Фон экрана», a pattern, light and motion behind the sheet; a time column without hours opens its day's spans on a tap. A quiet week line under each Sunday sums the week (a goal per week fills once reached). Other views: a week strip, a year in pixels for one column. «Оформление трекера» (the note's look sheet: color, paper, pattern, light, motion, scrapbook; owner: early) gives each tracker its own look, drawn muted under marks at half strength; in a wide window it is a pane beside the sheet, and it also sets the marks' color, their style (15, soft to snakes) and a grid, with many more colors and one's own (ADR-058). Where «Настроить трекер» lets them, columns stretch by their borders in the header (rows, in a month across). A wide month (a sleep sheet, days across) turns by pulling past its top or bottom, never sideways; on a phone it goes edge to edge, a finger paints hours by sliding along a row at once, and the sleep sheet's other columns slide out from the right (ADR-059). The constructor edits everything else: name, emoji, column colors (the editor's palette), column header texts, types, options with their colors and icons, units, goals, order; a column goes to the archive with its values, a tracker to the trash with «Вернуть». Home (ADR-034): a block leading to the trackers and a block per chosen tracker (S today's marks to tick, M its week, L its month). Android's widget «Трекеры»: today's marks of the first three trackers, a check or a count ticked in one tap without opening the app. The calendar shows a tracker only when its checkbox in the calendars' sheet is on (off by default): a quiet row of the day's marks in the day. Looks: everything is drawn from tokens through one look layer (icons, mark styles, the note-look layers), so the planned redesign (hand-drawn icons, paper effects, new colors) changes the drawing, not the data.

## Visual language
The identity is the "Admiral Benbow" inn (vision.md#identity): a cozy home base, warm light, parchment, ink, maps. Apply it lightly through the palette (warm neutrals, lantern amber, sea blue), paper textures, the icon, empty states and small illustrations. Avoid pirate kitsch and themed chrome that gets in the way. Material 3 + Expressive components and motion, behind our `BenbowTheme` tokens. Optional dynamic color, curated warm palettes. Bundled fonts with full Cyrillic (e.g. a UI sans like Onest/Manrope/Inter and a reading serif like Literata/Lora for journal text; final pick in the design pass). Fonts must be bundled for offline use, including on web. Note backgrounds are theme-aware color pairs + optional illustration/texture.
As built (6.5): "Ещё → Оформление" per device: Как в системе / Светлая / Тёмная, and palettes Таверна (default), Море, Пергамент, Цвета системы (Material You, Android). Palettes are complete M3 schemes generated from seed colors by MaterialKolor (HCT, like Material Theme Builder), so surfaces and containers carry the palette too. System bar icons follow the chosen mode. Note colors: an entry's menu → "Фон" (Keep's ten colors or none); the whole page and its card take the color. The name "Benbow" (the "Ещё" screen, the lock screen) is set in Meddon, a face after 18th-century English handwriting (OFL, docs/licenses/Meddon-OFL.txt); nothing else uses it. App icon (6.5): original vector art, the inn's brass lantern with a small flame and a warm halo over the night sea with a low wave; adaptive with a monochrome layer (themed icons); "Benbow Dev" shows it on slate with a stripe; the desktop window uses the same picture.
As built (7.22 S0-S2, ADR-057): every color comes from the theme: Material's roles and ours (`BenbowTheme.colors`: quiet words that still read 4.5:1, the disabled, lines, a board card, paper), never a hand-faded color or a hex table on a screen. In the light, white cards and sheets on a tinted page, and an open note on white paper like its card; the dark as it was. Words keep 4.5:1 on every ground (7:1 a note's words on its page and words on buttons and chips). The text colors keep their hues, turned a little toward the palette and deep enough to read; the note colors (notes, tags, categories, calendars) are the palette's own now, not Keep's: ten hues apart, as calm as the palette, a soft fill for pages and chips and a deeper mark for dots and names. Printed pages and drawings' SVG keep one fixed set (the default palette's light colors).
As built (7.22 S3-S7): «Оформление» starts with the theme: Тема (Как в системе / Светлая / Тёмная), Палитра (Таверна, Море, Пергамент, Лес, Сумерки, Чернила, Цвета системы where there are any, Своя), each card a sample in this device's mode; the palette is one for every device, the mode, Контраст (Как в системе / Обычный / Повышенный / Высокий) and Чёрный фон this device's. «Своя» opens a sheet: the theme it makes, light and dark side by side as it changes; Цвет (eighteen seeds round the wheel, Оттенок and Насыщенность sliders, HEX); Характер (Спокойная, Яркая, Выразительная, Верная цвету, Сдержанная, Монохром); Фон (В тон, Тёплый, Холодный, Серый); Второй цвет; «Готово» chooses it. ## Psychology
Evidence-informed practices exposed as **optional** templates, prompts and features. Never forced.
| Practice | Source idea | Feature |
|---|---|---|
| Expressive writing | Pennebaker: writing freely about emotions reduces stress | "Free write" mode: blank page, optional timer, private by default |
| Gratitude / Three Good Things | Seligman; Emmons & McCullough | Template + optional evening prompt |
| Affect labeling, emotional granularity | Lieberman; Feldman Barrett: naming emotions precisely regulates them | Mood check-in with an emotion-word picker (category "Emotions") |
| Cognitive reappraisal (CBT thought record) | Beck: situation → thought → feeling → evidence → balanced thought | Template |
| Self-distancing | Kross: reflect on yourself from a distance or in the third person | Retrospective comments on old entries, "write to past/future self" prompts |
| Savoring and reminiscence | Bryant | On this day, resurfaced favorites, yearly recap |
| Self-compassion | Neff | Prompts after low-mood check-ins ("what would you tell a friend?") |
| Small wins | Amabile, progress principle | Weekly review template, soft stats |
| Reflection cycles | — | Weekly/monthly review templates ("This week", "This month") |
Anti-patterns to avoid: streak loss shaming, forced daily prompts, gamified points, performance metrics, nagging notifications (reminders are opt-in, gentle, snoozable). Trackers (ADR-050) keep to it: an empty cell is blank paper, goals only fill a cell or a week when reached, totals count up and hide with one tap; no streaks, percentages or missed marks. App lock (biometric) for a sense of privacy. As built (6.4): "Ещё → Блокировка", see ADR-022; the lock screen asks at once and has "Открыть" to ask again.

## Performance budgets (validated in Phase 6 with macrobenchmarks)
Cold start to Home <600 ms on the owner's phone. Entry open <100 ms. Feed scroll: no janky frames at 120 Hz. Typing: no dropped frames on a 20k-char entry.

Measured in 6.7 (2026-10-14, S24+, `apps/benchmark` on the seeded bench build: 300 entries, 120 12-MP pictures; Android Studio mirroring was on, so absolute numbers are a little pessimistic):
- Cold start (time to first frame): 388 ms before (no R8, library profiles only) → 258 ms (R8 + the app's baseline profile). APK 44 → 8 MB.
- Feed skim (fast flings): frame overrun P90 / P95 / P99 = 2.7 / 7.1 / 16.6 ms before → 1.1 / 2.1 / 6.3 ms after parsing post text off the main thread, `contentType` and a cache window (a screen ahead, half behind). No main-thread frame over 8 ms left; by hand (adb swipes) 0.8% of frames miss the 120 Hz deadline.
- Entry open: settled in ~50 ms (3 frames of 14–22 ms: the post screen's first composition and text layout). Back to the feed costs one ~30 ms frame: Navigation3 drops the feed while a post is open, so it is composed and laid out again. Keeping it composed needs an overlay scene; postponed (one frame at the start of a fade).
- Typing: unchanged, see editor.md (fine to ~5k chars, long-form needs a chunked editor).

Measured in 7.13 N1 (2026-10-17, S24+, old and new feed built the same day; until then the seed was stopped after 10 s, partway, in every run):
- Feed skim, frame overrun P90 / P95 / P99: old 1.9 / 2.8 / 5.3-6.1 ms (300 posts at most), new 2.1 / 3.1-3.3 / 5.9-6.1 ms; a six-year journal (5,300 posts) 2.2 / 3.2 / 5.9, a far skim 1.9 / 2.7 / 4.8. The extra 0.2-0.3 ms are animation frames (the month under the title, «К сегодня»): twice as many frames run animations; moving windows recompose little (~10 ms per skim).
- Web (sql.js on this PC, 5,373 posts): the index takes 24 ms on the main thread each time the journal changes while the feed is open (a covering index would halve it; sql.js spends ~10 ms just handing over the rows); a window of 160 posts 2 ms. Opening the feed: at most 79 ms busy (the old feed of 300 posts: 123 ms), again 6-11 ms (old 51-72 ms).
